# HydraDB Storage Mechanics Explainer — "How HydraDB's Storage Layer Works"

An interactive, latency-correct explainer web application combining short narrative sections with a **real, WASM-compiled Rust storage engine** simulating disaggregated storage mechanics: **Memtable buffering**, **flush to object storage (S3)**, **compaction**, **multi-tier read path hierarchy**, and **zero-data-loss node crash recovery**.

---

## 🛠️ Architecture

The simulation is driven by an authoritative Rust storage engine compiled to WebAssembly (`wasm32-unknown-unknown`):

- **Memtable (`RAM`)**: Sorted `BTreeMap` key-value write-buffer. Latency cost logged: `~100ns` (`0.0001 ms`).
- **Local SSD Cache (`Local Cache`)**: Local disk cache storing recently accessed SSTables. Latency cost logged: `~0.5 ms`.
- **Mock Object Store (`S3`)**: In-memory cloud storage standing in for AWS S3 / SlateDB immutable SSTables. Latency cost logged: `~95.0 ms`.
- **Compaction**: Size-tiered compaction merging multiple Level 0 SSTables into Level 1 files, deduplicating keys by sequence number and reclaiming space. Latency cost logged: `~150.0 ms`.
- **Stateless Crash Recovery**: Node crash wipes RAM Memtable and Local Cache while keeping Object Store 100% intact. Subsequent reads fetch from S3 and lazily rebuild local SSD cache.

```

├── core/                         # Rust Crate (Storage Engine Core)
│   ├── Cargo.toml                # Cargo configuration & dependencies
│   └── src/
│       ├── lib.rs                # WASM bindings & Unit Tests

│       ├── object_store.rs       # Mock S3 object store & FlushedFile structs
│       ├── local_cache.rs        # Local SSD cache for SSTable files

├── index.html                    # Interactive web explainer & visualizer

```

## 🧪 Running Rust Core Unit Tests

To run the Rust core unit tests verifying flush correctness, compaction key deduplication, multi-tier read hierarchy, and crash recovery:

```bash
cd core
cargo test
```

### Test Suite Output:
- `test_write_and_memtable_read ... ok` (~100ns memory lookup)
- `test_flush_to_object_store_and_cache_read ... ok` (Flush creates immutable file & hits SSD cache)
- `test_crash_recovery_from_object_store ... ok` (Node crash wipes RAM/cache; reads fetch directly from S3)
- `test_compaction_deduplication ... ok` (Merging L0 files into L1 deduplicates duplicate key versions)

## 🔄 Rebuilding the WebAssembly Module

If you modify the Rust core in `core/src/`, rebuild the WASM module and update `index.html`:

### Prerequisites
- [Rust & Cargo](https://www.rust-lang.org/)
- `wasm32-unknown-unknown` target: `rustup target add wasm32-unknown-unknown`
- `wasm-bindgen-cli`: `cargo install wasm-bindgen-cli`

### Build Steps
```bash
# 1. Compile Rust core to release WASM target
cargo build --target wasm32-unknown-unknown --release --manifest-path core/Cargo.toml

# 2. Generate JS WebAssembly bindings into pkg/
wasm-bindgen core/target/wasm32-unknown-unknown/release/hydradb_storage_core.wasm --out-dir pkg --target web

# 3. Regenerate self-contained index.html
python scratch/build_site.py
```
